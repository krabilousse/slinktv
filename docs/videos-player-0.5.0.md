# Videos and compact player controls — 0.5.0

This release adds Videos next to Home and replaces the player's two rows of text buttons with one row of original vector icons. The focused action has a persistent text caption; play/pause has greater emphasis, chat has a separate selected state, and the bottom gradient keeps text readable over video. Metadata is smaller and stays above the actions. Live and VOD controls use the same visual language; VODs substitute seek and Start over actions for live/chat actions.

The layout follows [Android TV button hierarchy, icon controls, and linear navigation](https://developer.android.com/design/ui/tv/guides/components/buttons). [Android TV playback guidance](https://developer.android.com/training/tv/playback/controls) supports remote seeking; SlinkTV retains its established first-OK-reveals-controls and Back-to-catalog behavior. It uses ten-second preview steps rather than duration-proportional jumps, so a long archive is still navigable precisely. The implementation uses its own keyboard scrub state above Media3's time-bar renderer, avoiding Media3's default timeout/focus-loss commit. Timing is informed by the pinned Xtra/Twitch-box research; no upstream application implementation or icon assets were copied.

## Browsing behavior

Signed-in viewers see recent archives from followed channels; signed-out viewers see a sign-in action and no previous-account cards. All followed / Offline now filters the feed. The channel picker searches all cached follow membership and sorts channels with known recent archive dates first. It can immediately fetch an unscanned channel. Archive availability is not equivalent to last broadcast: streams whose VOD was never saved or has expired cannot be found through Get Videos.

Each scan uses up to 60 sequential channel requests, with a 250 ms gap after each response, through the existing serialized account worker. Each request gets the latest five archives. Check more starts another batch. A per-account cursor survives app restarts and advances on success, empty responses, and errors. Metadata stays in memory while MainActivity lives; successful entries expire after 15 minutes, empty entries after 30 minutes, and failures after one minute. Cache storage is capped at 1,000 channels / 5,000 video records. This is a partial discovery feed, not Twitch's private globally aggregated followed-video feed. No priority loop repeatedly starts at the same channels.

Channel-specific pages use 25 records with an explicit Older videos action and duplicate-cursor protection. Refresh on the broad feed reconciles follows through the account owner before fetching live status and archives. Complete live-followed queries establish offline status; after five minutes that status is unknown until refreshed. HTTP 429 stops discovery and observes the reported retry/reset interval, with a minimum one-minute pause. Prior cards survive failures. Hidden/background screens cancel their pending UI generations and stop scheduling new requests.

The implementation uses [Get Videos](https://dev.twitch.tv/docs/api/reference/#get-videos) with the existing own-client user token. Playback extraction remains anonymous Streamlink. Tokens are not sent to GraphQL, CDNs, or Streamlink. Channel titles are not mislabeled with the category currently being streamed. Cards show stream thumbnail, creator, title, creation age, duration, current channel status, and resume progress.

## Playback and remote behavior

- Archives explicitly start at zero or the saved position instead of the live edge. Quality changes and Activity stop/start preserve position and play/pause intention. Retry resolves fresh public URLs and retains the current quality when available.
- From hidden controls, Left/Right reveals the timeline and creates a ten-second pending target. Hold input is throttled to one change per 600 ms and uses minute steps after five seconds. Releasing the arrow leaves the target pending. OK commits one seek; Back or moving focus away cancels it. Timeline duration changes clamp the target. Icon seek buttons move ten seconds immediately and preserve play/pause state.
- Back otherwise returns to the catalog, preserving the existing live-player contract. Quality/chat dialogs close before leaving. Chat shortcuts and docked/overlay/hidden behavior remain available for live streams.
- Resume positions are separate from the optional live relevance history. They are capped at 200 entries, scoped to the account, checkpointed every 15 seconds and on lifecycle changes, and cleared on logout or in Settings. Near-end completion is applied only to static archives, not the temporary edge of a growing timeline. Pending scrub targets are never persisted as watched positions.
- Historical chat replay, chapter markers, bookmarks, playback-speed settings, offline downloads, and seek-thumbnail images are outside this increment. The existing live chat is not shown over an old VOD.
